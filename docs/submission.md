产品名称：Mac-Buddy · 麦麦搭子
参赛名称：Mac-Buddy 麦麦搭子——懂你口味的点餐助手
英文标语：Your taste. Your Buddy.

项目地址：https://github.com/`<你的 GitHub 用户名>`/mcd-buddy

项目简介：

Mac-Buddy 麦麦搭子——懂你口味的点餐助手，是基于麦当劳 MCP 的独立开发者作品，解决一个很小的真实问题：
点麦当劳最费神的不是「想吃什么」，而是「每次都要重新点一遍」。

它把你常点的那一套存成「老样子」，然后支持：一键照旧复用；只改一处、锁定不想动的（默认最多改 1 处，
一次替换计 1 处）；没想法时随机抽一份或抽今日一签；看懂这一餐的能量与蛋白质；
按「能量少一点 / 蛋白多一点 / 钠少一点」做有边界的替换；看看当前门店这一餐有没有可用券；
下单前一屏核对再确认。

技术上，后端是唯一持有 MCP Token 的一层，只监听 127.0.0.1；
业务规则全部下沉为**确定性纯函数**（不调 MCP、不读环境、不碰库），因此 113 个单元测试可以在完全离线、
强制演示模式下覆盖；随机结果由固定种子决定，同一天同一种子必得同一结果。

几条刻意坚持的边界：
营养数据只在规格与计量基准可核对时匹配，按「每份」累加而不做每 100g 换算，套餐不重复计入组成项，
缺失显示「暂无数据」而非 0，特制（如去酱）标注「变化未知」而不编造减少值，未设参考值时不给健康评分；
优惠券金额一律来自 calculate-price 实际核价，只有确实更便宜才显示「少付 ¥X」，不为凑券加东西；
商品图只使用 MCP 返回的官方 https 地址，失败降级为标注「示意图」的插画；
冲突时只说明原因并给出可放宽项，**绝不自动突破用户设的约束**；下单只能由用户明确确认后触发。

已实现：老样子模板与版本、差异对比、自然语言微调、微微调、随机来一份、今日食签、能量卡、
老样子轻一点、看看优惠、真实商品图、下单前核对、饮食足迹与口味画像。
规划中（尚未实现）：预约下单、多券叠加寻优、会员权益与积分。（不夸大，未实现的不写进能力）

真实接口已验证：门店查询、菜单、餐品详情、核价、历史订单、官方营养资料、门店优惠券（详见 MCP_INTEGRATION.md）。
因非营业时间未能完整验证：优惠核价的端到端下单链路（本项为安全起见也未实际下单）。
项目在演示模式下完全可运行，不需要 Token。

本项目使用 WorkBuddy 开发，参与「WorkBuddy 联动奖」评选（见 workbuddy.md）。
